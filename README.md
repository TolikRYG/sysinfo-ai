**SysInfo AI** — нативное приложение для Windows, которое собирает сведения о компьютере и помогает понять, что за ними стоит: для каких задач подходит конфигурация, где возможны узкие места и какие улучшения имеют смысл.

Инвентаризация работает локально. ИИ-анализ — отдельная, необязательная функция: выбранная копия отчёта отправляется в OpenRouter только после вашего подтверждения. Интерфейс не использует WebView, Electron, HTML или JavaScript.

## Скачать и запустить

**[Скачать sysinfo-ai.exe](./dist/sysinfo-ai.exe?raw=true)** — файл из папки `dist` текущей ветки репозитория.

Сохраните `.exe` в удобную папку и запустите. Установщик, Rust и средства разработки для запуска готовой сборки не нужны.

Целевая платформа — **Windows 10/11 x64**. Для интерфейса нужен рабочий графический драйвер с поддержкой OpenGL; часть сведений поступает через WMI. Интернет и API-ключ OpenRouter нужны только для ИИ-анализа, интернет без ключа — для загрузки каталога моделей по отдельной кнопке. Системные компоненты Windows по-прежнему необходимы: «один `.exe`» не означает независимость от ОС.

## Возможности

- **Оборудование по разделам.** Обзор, ОС, CPU, память, диски, GPU, плата и BIOS, сеть, процессы и полный JSON. Карточки распределяются по ширине окна; длинные разделы прокручиваются.
- **Понятный анализ.** Модель получает инструкцию объяснить конфигурацию, оценить типовые задачи, отметить возможные ограничения, дать 2–3 практических совета и назвать недостающие данные.
- **Настраиваемый интерфейс.** Светлая и тёмная темы, русский и английский языки. Язык нового ИИ-запроса определяется выбранным языком интерфейса и виден в подтверждении.
- **Экспорт и отзывчивость.** Копирование JSON и анализа, сохранение файлов, редактирование Markdown. Сбор, HTTP-запросы и запись файлов выполняются в фоновых потоках.

## Что собирается

| Раздел | Данные |
| --- | --- |
| ОС | Название и версии, hostname, архитектура, uptime, время загрузки. |
| CPU | Бренд, физические и логические ядра, сообщённая частота, загрузка, сведения по логическим процессорам; дополнительно сокеты и кэш через WMI. |
| RAM и swap | Общий, использованный, доступный и свободный объём; показатели swap. |
| Планки RAM | Слот, банк, производитель, part number, серийный номер, объём, сообщённые частоты, коды типа и форм-фактора, разрядность. |
| Тома и физические диски | Точки монтирования, ёмкость и свободное место, файловая система, съёмность; модели накопителей, прошивки, интерфейсы и статусы WMI. |
| GPU | Название, видеочип, драйвер и его дата, сообщённый режим экрана; отдельная инвентаризация DXGI с выделенной и общей памятью. |
| Плата и BIOS | Производитель, модель, версии, серийные номера и дата BIOS. |
| Сеть | Интерфейсы, MAC-адреса, накопленные счётчики байтов, пакетов и ошибок приёма/передачи. |
| Процессы | Топ-10 по памяти: имя, PID, резидентная память и загрузка CPU относительно всей системы. |

Полный отчёт также содержит время сбора, предупреждения и ограничения источников. Неизвестные значения могут быть представлены как `null`: это не обязательно означает отсутствие оборудования.

## Как пользоваться

### Локальный отчёт

При запуске начинается локальный сбор. Откройте нужный раздел вкладки **«Система»**. Кнопка **«Обновить данные»** создаёт новый снимок; приложение не является непрерывным аппаратным монитором.

Для экспорта используйте **«Скопировать JSON»** или **«Сохранить в файл»**. Полный JSON доступен и в отдельном разделе.

### ИИ-анализ

1. Выберите **RU** или **EN** до запуска нового анализа и откройте вкладку **«ИИ-анализ»**.
2. Введите API-ключ OpenRouter, выберите модель из списка или укажите её ID вручную. Каталог можно загрузить отдельной кнопкой; встроенные примеры не гарантируют доступность модели.
3. Настройте скрытие идентификаторов, включение процессов и параметры запроса. Нажмите **«Проанализировать через ИИ»**.
4. Проверьте модель, язык ответа и точный JSON в окне подтверждения, отметьте согласие и нажмите **«Отправить»**. Полученный Markdown можно отредактировать, скопировать и сохранить.

Язык фиксируется для подтверждённого запроса. Переключение RU/EN не переводит уже полученный текст и не меняет запрос, который выполняется. Модель может нарушить языковую инструкцию; для нового результата требуется новый подтверждённый запрос.

### Сохранение

| Файл | Содержимое |
| --- | --- |
| `system_report.json` | Полный локальный отчёт. |
| `ai_analysis.md` | Текущий текст анализа, включая ваши правки и метаданные ответа. |

По умолчанию файлы сохраняются рядом с `.exe`. В диалоге можно указать другой абсолютный путь; папка должна существовать и быть доступной для записи. Перед заменой существующего файла показывается предупреждение.

## Приватность

**API-ключ не записывается приложением на диск.** После подтверждённого запуска запроса поле ключа очищается. Приложение не сохраняет настройки и не запускает ИИ-запросы автоматически. Это не обещание безопасного стирания всех копий ключа из памяти, буфера обмена или дампов ОС.

Для ИИ по умолчанию скрываются hostname, MAC, серийные номера, имена интерфейсов и томов, пути монтирования. Подробные сообщения ошибок заменяются нейтральными; топ процессов не включается. Полный локальный отчёт при этом не меняется. Модели оборудования остаются в отправляемых данных — скрытие идентификаторов не гарантирует анонимность.

> [!IMPORTANT]
> Подтверждённый запрос передаёт данные OpenRouter и провайдеру модели и может быть платным. Фильтр `data_collection=deny` не означает универсальной гарантии нулевого хранения. Проверяйте настройки сервиса и провайдера; не публикуйте ключи и необезличенные отчёты.

Автоматических повторов платных запросов нет. Тайм-аут или закрытие приложения не гарантируют отмену запроса, уже принятого провайдером. Предыдущий успешный анализ сохраняется в интерфейсе, если новый запрос завершился ошибкой.

## Ограничения

Снимок конфигурации — **не бенчмарк и не проверка исправности**. Разовая загрузка не доказывает постоянное узкое место. Температуры, SMART, ресурс SSD, состояние БП и загрузка GPU здесь не измеряются.

Значения частот передаются так, как их сообщает источник. Память показывается в бинарных единицах GiB/MiB. Общая память GPU не прибавляется к выделенной VRAM; WMI `AdapterRAM` не считается надёжным точным объёмом большой видеопамяти. Тома и физические накопители не следует считать дважды, а накопленный сетевой трафик — принимать за скорость интернета.

Доступность сведений зависит от ОС, драйверов, прошивки и прав доступа. Рекомендации ИИ могут содержать ошибки: проверяйте совместимость комплектующих перед покупкой или изменением конфигурации.

## Сборка из исходников

Для сборки на Windows нужны Rust stable с целью `x86_64-pc-windows-msvc`, Microsoft C++ Build Tools с компонентами C++ для рабочего стола и Windows SDK. Настройки toolchain находятся в [`rust-toolchain.toml`](./rust-toolchain.toml).

В корне проекта выполните:

```powershell
.\build.cmd
```

Сценарий создаст `Cargo.lock`, если его нет, выполнит форматирование, `cargo check`, обычные unit-тесты и release-сборку. При ошибке обязательного этапа он остановится. После успешного выполнения результат копируется в:

```text
dist/sysinfo-ai.exe
```

Сохраняйте полученный `Cargo.lock` в репозитории. Release-профиль использует `lto = true`, `strip = true` и статическую линковку CRT для Windows MSVC; интерфейс работает через Glow/OpenGL.

Дополнительные проверки после разрешения зависимостей:

```powershell
cargo test --locked --all-targets
cargo clippy --locked --all-targets
```

Отдельная проверка реального оборудования Windows:

```powershell
cargo test --locked real_windows_collection_smoke_test -- --ignored --nocapture
```

Наличие тестов в исходниках не означает, что конкретная опубликованная сборка прошла все проверки.
