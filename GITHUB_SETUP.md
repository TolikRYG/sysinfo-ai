# Публикация README и кнопки скачивания

Этот комплект содержит только документацию. Исполняемый файл не включён, репозиторий на GitHub не изменён.

## Размещение

Положите `README.md` и `README.en.md` **в корень репозитория**, рядом с `Cargo.toml`. Русская версия будет основной, кнопка English открывает английскую. Оба файла используют одну относительную ссылку:

```text
./dist/sysinfo-ai.exe?raw=true
```

Имя владельца, название репозитория и ветку подставлять не нужно. GitHub разрешает относительные ссылки с учётом текущего файла и ветки. README рассчитаны на просмотр в репозитории GitHub, не на GitHub Pages. См. [документацию относительных ссылок](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#relative-links).

Кнопка оформлена статическим бейджем [Shields.io](https://shields.io/badges/static-badge). Под ней есть обычная текстовая ссылка на тот же файл, которая не зависит от загрузки изображения бейджа.

## Подготовка файла

Соберите и проверьте текущую версию приложения:

```powershell
.\build.cmd
```

Продолжайте только после успешной сборки и проверки полученного приложения. Сценарий проекта копирует готовый файл в `dist/sysinfo-ai.exe`. Локального наличия файла недостаточно: для кнопки нужно опубликовать его в той же ветке GitHub, что и README.

## Исправление .gitignore

В исходном проекте каталог `/dist/` целиком исключён. Замените именно эту строку на:

```gitignore
/dist/*
!/dist/sysinfo-ai.exe
```

Не оставляйте рядом старое правило `/dist/`: нельзя вернуть отдельный файл, пока исключён его родительский каталог. Остальные правила проекта сохраните. При необходимости защитите экспортированные отчёты во всех папках:

```gitignore
system_report.json
ai_analysis.md
.env
*.tmp
```

Правила игнорирования не удаляют уже отслеживаемые файлы из репозитория или его истории. См. [gitignore](https://git-scm.com/docs/gitignore).

## Публикация

Следующие команды предназначены для существующего клона вашего репозитория с настроенным удалённым репозиторием и upstream текущей ветки:

```powershell
git add -- README.md README.en.md .gitignore dist/sysinfo-ai.exe
git diff --cached --name-only
```

Проверьте **весь** подготовленный список: в нём не должно быть ключей, личных отчётов или других непредназначенных для публикации файлов. После проверки:

```powershell
git commit -m "Add Russian and English README with Windows download"
git push
```

Название и регистр файла должны совпадать точно: `dist/sysinfo-ai.exe`.

## Проверка кнопки

Откройте README на GitHub, перейдите по кнопке и проверьте загруженный файл. Затем переключитесь на English и повторите проверку. Для общедоступного скачивания репозиторий должен быть публичным; в приватном репозитории читателю потребуется доступ.

Сравнить SHA256 локальной сборки и скачанного файла можно через `Get-FileHash -Algorithm SHA256 -LiteralPath "путь-к-файлу"`.

Если появляется 404, проверьте наличие `.exe` именно на GitHub в текущей ветке, путь, регистр и права доступа. Если скачивается небольшой текстовый указатель Git LFS вместо `.exe`, проверьте правила `.gitattributes` и способ публикации бинарного файла.

Через веб-интерфейс GitHub можно загрузить файл не более 25 MiB; обычный Git блокирует файлы больше 100 MiB. Для больших бинарных файлов нужен другой способ публикации, например GitHub Releases, и соответствующая замена ссылки в README. См. [ограничения GitHub](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).
